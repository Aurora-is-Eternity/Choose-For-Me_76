# ADR-0001：为什么选 MIT

- 状态：已接受
- 日期：2026-11-02
- 决策者：潘阳

## 背景

这是一个「随手打开、随手用」的小工具，代码量小、单人维护、没有商业计划。
许可证要解决的问题其实只有两个：

1. 别人（同学、社团、老师）能不能直接拿去用、改、再发；
2. 我自己会不会因为「没写许可证」而让仓库在法律上不可用。

## 候选方案

| 许可证 | 核心条款 | 适用场景 |
| --- | --- | --- |
| **MIT** | 保留版权声明即可随意使用、修改、分发、商用 | 希望被最广泛地使用 |
| Apache-2.0 | MIT 的能力 + 明示专利授权 + 商标条款 + NOTICE 要求 | 有专利风险、需要企业采用 |
| GPL-3.0 | 衍生作品必须以 GPL 开源（传染性） | 希望强制下游开源 |
| Unlicense / CC0 | 放弃一切权利 | 完全不在乎归属 |

## 决策

选择 **MIT**。

理由：

1. **目标是「被人用」而不是「被人尊重」**。这个项目的价值全在「打开就用」，
   任何额外的合规成本都会劝退第一个想用的人。
2. **没有专利筹码**。单人课程项目不涉及需要明示授权的专利，Apache-2.0 的专利条款
   在这里没有实际收益，却带来 NOTICE 文件的维护成本。
3. **传染性会挡住最想要的那类用户**。如果社团想把它嵌进自己的小程序里，
   GPL 会让对方重新考虑；而本项目并不指望靠「强制开源」获得回馈。

## 已知代价

| 代价 | 影响 | 何时值得重新考虑 |
| --- | --- | --- |
| 没有明示专利授权 | 若有专利纠纷，贡献者与使用者缺少明确保护 | 有企业用户提出要求时，可考虑双许可或迁到 Apache-2.0 |
| 没有商标条款 | 别人可以拿这个名字做宣传 | 出现冒名产品时，补一个商标政策即可 |
| 不要求下游开源 | 改进可能不会回流 | 若成为课程公共基础设施，可考虑 GPL 以强制回流 |

迁移成本：MIT → Apache-2.0 只需替换 LICENSE、补 NOTICE、在 README 说明，
历史提交不必重写（旧版本仍按 MIT 授权，这一点要在 CHANGELOG 里写清）。

## 结论

在「最大传播」与「最小摩擦」之间，MIT 是唯一不需要解释的选择。
把省下来的合规成本，花在把选项库做厚上。
